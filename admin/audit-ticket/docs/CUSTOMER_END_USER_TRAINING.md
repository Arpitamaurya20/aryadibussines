## Module 1 — 4 minutes | My Branch Dashboard

**Menu:** My Branch Dashboard  
**Who:** Branch Account Manager (BAM) — branches assigned to you only

### What you see
- Live wallboard for **your branches only**
- Ticket counts by status (open, closed, in progress)
- Quotations, technicians, and branch-wise breakdown
- Filters: period, company, branch, ticket type

### How to use (2 min)
1. Log in → open **My Branch Dashboard** from the left menu  
2. Select **period** (current FY, this month, or custom dates)  
3. Use **company / branch** filters to focus on one site  
4. Click status tiles or charts to understand workload  

### When to use (1 min)
- Start of day — see pending tickets across your branches  
- Before assigning technicians — check open load per branch  
- Weekly review — ticket and quotation trends  

### Remember
- You only see branches where you are the **Account Branch Manager**  
- If you also have state access, use **State Dashboard** instead for wider view  

---

## Module 2 — 4 minutes | My State Dashboard

**Menu:** My State Dashboard  
**Who:** State Corporate Lead — all branches in your state(s)

### What you see
- Same wallboard style as branch dashboard, but for **entire state**
- All companies and branches in your mapped state(s)
- Ticket status, quotations, regional view

### How to use (2 min)
1. Log in → open **My State Dashboard**  
2. If you manage multiple states, pick **state** from filter  
3. Filter by company, ticket type (R&M, PPM, Projects, etc.)  
4. Review open vs closed tickets for the period  

### When to use (1 min)
- State-level daily stand-up  
- Identify branches with high open ticket count  
- Before **verify tickets** or escalation review  

### Branch vs State dashboard

| | Branch Dashboard | State Dashboard |
|---|------------------|-----------------|
| **Scope** | Your assigned branches | Full state |
| **Role** | Branch Account Manager | State Corporate Lead |
| **Use for** | Day-to-day branch ops | Oversight & verification |

## Module 3 — 3 minutes | Reassign technician

**Where:** Corporate Tickets → open ticket → **Assignment** tab  
**Who:** Authorized manager (BAM, escalation handler)

### When to reassign
- Technician on leave  
- Wrong technician assigned  
- Site needs different skill set  
- After escalation — send back to field with new technician  

### Steps (2 min)
1. Open the **corporate ticket**  
2. Go to **Assignment** tab  
3. Select **new technician** from dropdown  
4. Add **remarks** (reason for reassignment)  
5. Click **Reassign**  

### What happens
- Ticket moves to the new technician  
- **Active escalation is cleared**  
- Due date is updated (typically +1 day)  
- History records who reassigned and when  

### Rules
- Cannot reassign **closed** or **cancelled** tickets  
- Must pick a **different** technician (same person not allowed)  
- Always add a clear remark for audit trail

## Module 4 — 4 minutes | Ticket escalation

**Where:** Corporate Tickets → open ticket → **Assignment** tab → Escalation section  
**Who:** Branch manager, state manager (by level)

### Why escalation exists
If a ticket is **not resolved by due date**, it escalates up the chain so nothing is missed.

### Escalation levels (automatic)

```
Branch Manager  →  State Manager  →  CEO
     (L1)              (L2)          (L3)
```

- Each level gets a **response window** (hours to act)  
- If no action, ticket **auto-escalates** to next level  
- Ticket status becomes **Escalated**  

### Manual escalation (1 min)
1. Open ticket → Assignment tab  
2. Under **Manual Escalation**, choose level  
3. Add reason → click **Escalate Now**  
4. Use when issue is urgent — do not wait for due date  

### After escalation (1 min)
- Escalated person sees ticket in their queue  
- **Reassign to technician** clears escalation and sends work back to field  
- Check **Escalation History** on the same tab

## Module 5 — 4 minutes | Verify tickets

**Where:** Corporate Tickets list → **Verify** icon / State Manager Ticket Verification  
**Who:** State Corporate Lead or Branch Account Manager (Admin also)

### Purpose
Before a ticket can move to **billing**, a manager must confirm quality and documentation.

### Verification checklist
Tick all that apply before clicking **Verify Ticket**:

| Check | Meaning |
|-------|---------|
| Quality of ticket satisfactory | Work quality OK |
| Digital report complete | Service report / digital docs done |
| WCC checked | Work completion certificate checked |
| Vendor payment checked | Vendor side reviewed |
| Quotation quantity checked | Qty matches quotation |
| DPR checked | *(Project tickets only)* Daily progress report checked |

### Steps (2 min)
1. Open ticket from corporate tickets list  
2. Click **verify** (green/red icon shows current status)  
3. Complete **all checklist items**  
4. Click **Verify Ticket**  

### After verification
- Ticket shows **verified** icon (green check)  
- Ticket becomes **eligible for billing queue**  
- Unverified tickets do **not** appear in billing “Eligible” tab

## Module 6 — 5 minutes | Ticket billing

**Menu:** Ticket Billing  
**Who:** Billing / accounts team (role: Ticket Billing)

### Purpose
Move closed, verified tickets through billing stages until invoiced and paid.

### Billing queue tabs

| Tab | Stage | Meaning |
|-----|-------|---------|
| **Select for Billing** | Eligible | SM-verified, unbilled — pick tickets to bill |
| **Ready for Billing** | ReadyForBilling | Selected — ready to create invoice |
| **Billing Verification** | BillingVerification | Under accounts review |
| **Payment Status** | PaymentStatus | Invoice sent — track payment |
| **Partial Billing** | PartialBilling | Part billed or part paid |

### Workflow (3 min)

**Step 1 — Eligible**  
- Tickets appear here only after **State Manager verification**  
- Select tickets → move to **Ready for Billing**  

**Step 2 — Ready for Billing**  
- Review amounts, PO, branch details  
- Generate / attach billing → move to verification or payment stage  

**Step 3 — Payment**  
- Update payment status (Paid / Partially Paid / Pending)  
- Partial cases stay in **Partial Billing** tab  

### Filters
- Date range, company, branch, state, region, ticket type  
- Use filters to process one client or one state at a time  

### Remember
- **No verification = not in Eligible tab**  
- Always confirm ticket is **closed** and documentation complete before billing

## Module 7 — 4 minutes | Employee asset acknowledgement

**Menu:** Employee Asset Acknowledgement (admin)  
**Public form:** Link sent to employee  
**Who:** HR / admin assigns assets; **employee** acknowledges on phone or laptop

### Purpose
Record company assets issued to employees (laptop, mobile, tools, vehicle, etc.) and get **digital acknowledgement** from the employee.

### Admin — assign assets (2 min)
1. Open **Employee Asset Acknowledgement**  
2. Select **employee**  
3. Add assets: category, serial number, description, issue date  
4. Save — status shows **Pending Acknowledgement**  
5. Click **Send link** / copy **public form link** to employee  

### Employee — acknowledge (1 min)
1. Open link received (SMS / email / WhatsApp)  
2. Review list of assets assigned  
3. Confirm each item or acknowledge all  
4. Submit — status changes to **Acknowledged**  

### Asset hold statuses (admin updates later)

| Status | When used |
|--------|-----------|
| With Employee | Normal — actively assigned |
| Returned | Asset returned to company |
| Lost / Missing | Asset lost |
| Damaged | Asset damaged |
| Retired | Written off |

### Remember
- Link is **employee-specific** — do not share with others  
- Pending items block clean HR record — follow up until acknowledged

## Full process flow (how modules connect)

```
Ticket raised
    ↓
Technician works on site (mobile app)
    ↓
Branch Dashboard / State Dashboard — monitor progress
    ↓
Due date missed? → Escalation (Module 4)
    ↓
Need different tech? → Reassign (Module 3)
    ↓
Ticket closed + reports complete
    ↓
Verify ticket (Module 5)
    ↓
Ticket Billing (Module 6)
    ↓
Payment complete
```

**Parallel process:** HR assigns company assets → employee acknowledges (Module 7)
